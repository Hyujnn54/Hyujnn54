# README Review And Rewrite Template

Use this file in a future session when you want the same kind of cleanup, restructuring, and documentation work on another project.

## How To Use It

Open the target repository in VS Code, then paste the request below and fill in the project-specific details.

## Reusable Request

```text
Review and improve this repository like you did for my networking project.

Goals:
- Make the README cleaner, more professional, and recruiter-friendly
- Remove low-value or repetitive content
- Add missing structure and documentation where needed
- Add diagrams only if they improve clarity and look professional
- Keep the project description truthful to my actual contribution
- Suggest what should stay, what should be removed, and what should be added

Tasks:
1. Review the current README and repository structure
2. Rewrite the README with better structure, clearer sections, and stronger technical framing
3. Use screenshots or documentation files if they exist
4. Add a Mermaid diagram if it genuinely helps explain the architecture or workflow
5. Remove unnecessary sections, weak wording, or clutter
6. Keep the final result concise, technical, and portfolio-ready
7. If appropriate, update my profile README to link to this project more effectively
8. Commit and push only if I ask for it

Project details:
- Project name: <replace>
- Target audience: recruiters / engineers / both
- My contribution: <replace with what you personally did>
- Stack: <replace>
- Team or solo: <replace>
- Available assets: screenshots / PDF / presentation / diagrams / none
- Important constraints: do not invent features, do not exaggerate my role, keep it professional

What I want from you at the end:
- A cleaned and improved README
- A short review of what was weak before
- Suggestions for the next improvement steps
```

## What To Provide For Best Results

- A repository with the real project files
- A few screenshots with clear names
- Any PDF or report only if it adds technical detail
- A short note describing exactly what you built versus what teammates built

## Good Default Rules

- Prefer clarity over decoration
- Prefer architecture, contribution, outcomes, and screenshots over badge clutter
- Prefer one useful diagram over multiple decorative ones
- Do not keep auto-generated sections unless they add real value
- Keep the README readable in under 2 minutes

## Optional Add-On Request For Profile README

```text
After improving this project README, update my profile README so the project is represented clearly and concisely. Keep the profile focused on my strongest projects and remove unnecessary sections.
```
